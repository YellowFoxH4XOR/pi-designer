# Design references: update feature

The approved source set is XIAS, Material Design 3, shadcn/ui and Figma Community kits. UIZZE is deliberately excluded. The bundled Material and shadcn design systems are still the visual contract when selected; upstream text is reference material, never an override.

## Behavior

Settings → Design references groups approved sources by design guidance, shadcn ecosystem and Figma kits. XIAS design QA, shadcn's documentation index, Material Color Utilities, Figma's open-source Simple Design System, and the ReUI, Magic UI, Kokonut UI and shadcn/studio repository overviews can be checked (manually or every 24 hours **while the app remains open**), previewed as plain text and applied with an explicit action. Check alone never installs. Updated documents are stored in `~/Library/Application Support/PiDesigner/knowledge/` (or the configured data directory), not the signed `.app` bundle. Hashes guard pending and installed content; writes use a temporary file and atomic rename. A failed fetch leaves the installed document intact. The previous installed version is retained for a one-click Restore previous action. No code, npm packages, Figma kits, fonts or images are downloaded. The official Material Design site, Figma Community kits, Obra's Community Edition and Aceternity UI are browse-only because those page/asset terms differ from the linked open-source documentation. An overview/README is not a component catalog, and none of these resources installs React components into πDesigner.

The agent sees a list of **reviewed reference paths**, not their bodies in the system prompt. At run start, a local, explainable router infers intent from the brief and chooses at most two source roles. The route and reasons are included in that turn and in the durable run context shown in Studio. For sources with a text endpoint, a verified installed reference is preferred; otherwise the updater may fetch its allowlisted text into the *unreviewed cache* for this run. This cache is not applied as a reviewed document and cannot override the selected design system or the workflow. Fetch failure falls back to bundled craft guidance. Browse-only sources remain pointers: the prompt never claims to have read them. The model is asked to read matching available references before new builds, name its source trade-off and adjust a provisional selection if the brief warrants it. This is an explainable heuristic, not a trained quality ranker or a guarantee that a source was actually read; tool activity reveals reads. New conversations pick up new reviewed references without a build. Existing π sessions may retain earlier system prompts: start a new conversation after installing new references. The updater never runs external code or edits bundled skills or prompts.

Endpoints on the local daemon: `GET /api/knowledge`, `POST /api/knowledge/{id}/check`, `GET /api/knowledge/{id}/preview`, `POST /api/knowledge/{id}/apply`, `POST /api/knowledge/{id}/rollback`. Only fixed allowlisted URLs and IDs are permitted. Fetches require HTTPS, are limited to 512 KiB, and reject cross-host redirects; browser writes require same Origin. Files are private to the local account.

## Next increments

- Add an optional, curated signed manifest to update approved source locations independently of app releases, with a reviewable diff and rollback, rather than following arbitrary URLs from remote text.
- Add a stable, explicitly licensed full Material guidance export if available; the Material Color Utilities README is not a substitute for Material 3 guidance. Leave Figma Community files as links until individual kit authors grant compatible reuse.
- Provide a side-by-side text diff before applying; basic per-source rollback is already available. Keep *installation* opt-in even when the router safely reads a cached reference.
- Measure route precision on real briefs and make mismatches correctable in Studio; expand domain-specific guidance before claiming autonomous taste. Router selection is intentionally conservative.

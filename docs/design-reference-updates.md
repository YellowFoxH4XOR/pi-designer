# Design references: update feature

The approved source set is XIAS, Material Design 3, shadcn/ui and Figma Community kits. UIZZE is deliberately excluded. The bundled Material and shadcn design systems are still the visual contract when selected; upstream text is reference material, never an override.

## Behavior

Settings → Design references groups approved sources by design guidance, shadcn ecosystem and Figma kits. XIAS design QA, shadcn's documentation index, Material Color Utilities, Figma's open-source Simple Design System, and the ReUI, Magic UI, Kokonut UI and shadcn/studio repository overviews are approved downloadable text. They sync automatically when the app starts and every 24 hours while it is running; changed verified documents are installed in the background. Settings shows each guide's state (ready, waiting, failed with the last good copy kept, or link only) with **Sync now** and per-source **Restore previous**; there is no manual review step. The per-source check, preview and apply endpoints remain for API clients. Documents are stored in `~/Library/Application Support/PiDesigner/knowledge/` (or the configured data directory), not the signed `.app` bundle. Hashes guard pending and installed content; writes use a temporary file and atomic rename. A failed fetch leaves the last working document intact and records an error for that source. The previous installed version is retained for a one-click Restore previous action, including after an automatic update; a rollback lasts until the next startup or scheduled sync. No code, npm packages, Figma kits, fonts or images are downloaded; full repositories are not cloned or mirrored, and automatic syncing does not update the bundled source catalog. The official Material Design site, Figma Community kits, Obra's Community Edition and Aceternity UI are browse-only because those page/asset terms differ from the linked open-source documentation. An overview/README is not a component catalog, and none of these resources installs React components into πDesigner.

The agent sees a list of **installed reference paths**, not their bodies in the system prompt. Installation does not mean a user reviewed the text. At run start, the model sees the allowlisted source metadata (names, use cases, licensing notes, availability)—**not a hard-coded source choice**. For a new design it chooses zero to two sources through `select_design_sources`, explaining the user goal and trade-off. The tool validates IDs against the local catalog and records the actual choice in Studio's durable run context. For selected sources with a text endpoint, a verified installed reference is preferred; otherwise the updater may fetch its allowlisted text into a temporary cache for this run. That cache is not an installed reference and cannot override the selected design system or workflow. Fetch failure falls back to bundled craft guidance. Browse-only sources remain pointers: the prompt never claims to have read them. The model is asked to read selected available references before new builds. Its choice and trade-off are visible, but the model can still choose poorly: the selection is not a verified quality score, and only tool activity proves it read a document. If no reference is relevant it may choose none. New conversations pick up the latest installed references; existing pi sessions may retain earlier system prompts. The updater never runs external code or edits bundled skills or prompts.

Endpoints on the local daemon: `GET /api/knowledge`, `POST /api/knowledge/sync`, `POST /api/knowledge/{id}/check`, `GET /api/knowledge/{id}/preview`, `POST /api/knowledge/{id}/apply`, `POST /api/knowledge/{id}/rollback`. Only fixed allowlisted URLs and IDs are permitted. Fetches require HTTPS, are limited to 512 KiB, and reject cross-host redirects; browser writes require same Origin. Files are private to the local account.

## Verification — 2026-10-23

- `go test -race ./...` and `go vet ./...` passed. Sync coverage exercises changed and unchanged documents, rollback preservation, independent source failures, invalid documents, recovery, cancellation, and immediate/periodic worker execution.
- UI tests and TypeScript checking passed. `./scripts/build-mac.sh` rebuilt and verified the ad-hoc signed app.
- A real daemon with isolated temporary data downloaded and installed all eight approved text references on startup; four browse-only sources remained links.
- Restarting with outbound HTTP routed through an unavailable local proxy exposed eight per-source failures while preserving all eight installed hashes. Both daemon instances exited cleanly.
- Browser inspection confirmed the installed count, source failures, and subsequent automatic `/api/knowledge` polling without a reload. No browser errors were recorded.

## Next increments

- The approved source list and locations are fixed in the bundled catalog; a future signed manifest could update them independently of app releases, with a reviewable diff and rollback, rather than following arbitrary URLs from remote text.
- Add a stable, explicitly licensed full Material guidance export if available; the Material Color Utilities README is not a substitute for Material 3 guidance. Leave Figma Community files as links until individual kit authors grant compatible reuse.
- Show a text diff of what an automatic update changed; per-source rollback is already available.
- Measure the model's source-selection quality on real briefs; add a user override and richer evidence before claiming autonomous taste. The app's validator controls access and provenance, not the decision.
